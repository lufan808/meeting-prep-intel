# Portable Pre-Meeting Intel

> 在第一次见面前，快速研究一个人最近正在做什么、说什么，以及外界如何理解他。

一个面向 Codex 和 Claude Code 的会前人物情报 Skill。它从公开来源中提取最近信号，建立本人叙事与外部叙事的对照，并生成一份可以直接带进会议的简报。

## 它做什么

一次调用完成四路研究：

1. **本人表达**：近期文章、访谈、播客、演讲、社交媒体和产品动作；
2. **社群反应**：行业社区、论坛、回复和讨论中的真实反应；
3. **第三方视角**：媒体、分析师、行业评论和专业机构如何描述这个人；
4. **身份与官方基线**：优先官网、雇主页面、官方团队页、官方会议资料和公司新闻稿；LinkedIn 与个人简介作为自述身份来源；供应商/制作方案例只证明项目参与，不作为当前职位的首要身份依据。

它重点寻找的不是一份旧简历，而是：

- 这个人在最近 90 天最重要的叙事主线；如果 90 天信息不足，再扩展到 180 天并说明原因；
- 他希望别人相信什么；
- 他正在建设、推动、改变或挑战什么；
- 本人如何描述自己，外界又如何理解他；
- 你在会面中可以自然提出的具体问题。

## 怎么用

```text
/portable-pre-meeting-intel [姓名] [可选：公司 / 角色 / 会面目的]
```

例如：

```text
/portable-pre-meeting-intel Rory Sutherland 营销投放、品牌建设和效果衡量
```

也可以直接用自然语言：

```text
准备我和 Rory Sutherland 的会面，重点了解他最近对营销投放、品牌建设和效果衡量的看法。
```

默认先研究最近 **90 天**。如果 90 天内不足以回答会面问题，再扩展到最近 **180 天**，并在输出中同时写明初始窗口、实际窗口和扩展原因。如果用户指定“最近 30 天”“最近半年”等时间范围，则以用户指定的范围作为初始窗口；输出仍需写明生成日期和实际起止日期。

## 研究流程

```text
Step 0      解析姓名、上下文和初始信号窗口（默认 90 天）
            └─ 信息不足时扩展至 180 天，并记录扩展原因
Step 0.5    身份预检：优先确认官方雇主/组织页面，再用 LinkedIn 或其他自述资料交叉验证；供应商案例不作为首要身份来源
Step 1      四路并行研究
            ├─ A. 社群讨论
            ├─ B. 本人近期表达
            ├─ C. 第三方媒体与行业评论
            └─ D. 官方身份与自我描述

Step 1.25   处理用户提供材料
            └─ 单独提取项目方材料中的事实，并标注待核实事项

Step 1.5    可选的信源增强
            └─ 将已验证的社交账号主页升级为真实内容链接

Step 2      校准来源、归因和冲突；合成当前叙事与自述/外界对照
Step 3      质量检查并输出 Markdown 会前简报；如环境支持，也可继续生成文档
```

## 运行说明

这个 Skill 不绑定特定的 Agent 平台。当前环境支持并行任务时，四条研究线可以并行执行；不支持时，仍按同样的四条线依次完成。可选的信源增强能力不可用时，只会降低具体社交内容链接的精度，不会阻塞简报生成。

如果用户提供 PDF、项目介绍、会议材料或其他文档，Skill 会把它作为独立的“用户提供材料”层处理：提取其中的日期、人物、项目、数据和定位，但不会把它自动当作公开事实。与公开来源不一致的地方会单独列出，转化为会面中的待核实问题。

## 飞书 / Lark 文档模式

默认以聊天消息作为唯一输入，不要求用户先去飞书文档里填写一遍。用户在对话中提出研究需求后，如果当前环境已经连接飞书文档创建能力，Skill 可以直接创建一篇新的飞书文档作为结果。

如果用户已经提供了一篇飞书文档链接，则更新这篇已有文档；否则创建新文档。两种情况下，都要把聊天中的原始需求和解析后的研究参数放在文档顶部。

推荐的文档结构：

```text
会前人物研究
├── 研究输入
│   ├── 原始需求：聊天中的完整请求
│   ├── 人物：
│   ├── 公司 / 角色：
│   ├── 会面目的：
│   ├── 初始研究范围：最近 90 天
│   ├── 实际研究范围：90 天；不足时扩展为 180 天
│   └── 扩展原因：若发生扩展，必须明确写出
└── 研究结果
    └── 六段式会前简报
```

调用示例：

```text
研究 Rory Sutherland 最近 90 天的公开动态；如果信息不足，再扩展到 180 天，
重点了解他对营销投放、品牌建设和效果衡量的看法，并生成飞书会前简报。
```

生成的文档顶部会保留本次聊天中的原始需求，下面展示人物、上下文、会面目的和研究范围，之后才是完整研究结果。飞书文档能力不可用时，Skill 会输出同样结构的 Markdown 简报，不会假装已经创建或写入飞书文档。

## 产出什么

一份适合会前 10–15 分钟阅读的简报，顶部是身份卡与当前叙事主线，正文包含六部分：

1. **人物背景与关键转折**，解释他为什么走到今天；
2. **有效研究窗口内的关键事件**，区分本人表达与外部解读，并标注来源、可信度和时效；
3. **他怎么看自己 vs 外界怎么看他**；
4. **工作方式与价值判断**，把解释性判断标成推断；
5. **会面准备**，包含待核实事项和三条可以直接开口的问题；
6. **数据可信度、来源限制和搜索备注**。

每个重要结论都绑定已打开的来源。无法验证的社交媒体具体链接会保留账号主页，并明确标注需要手动定位，不会猜测 URL 或 status ID。

## 可选的信源增强层

会前研究里经常遇到一个问题：搜索结果能证明“某人在 X 上讨论过某个主题”，但只能找到账号主页，无法安全地猜出具体 post URL。

当运行环境提供实时公开社交媒体检索能力时，可以在信号较新、且账号主页是唯一已验证链接的情况下：

- 拉取目标人物近期公开动态；
- 用关键词检索相关内容；
- 返回真实的内容 URL、原文摘录和发布时间；
- 帮助把账号主页升级为可核验的具体内容链接。

具体可检索的平台取决于当前运行环境提供的工具。

信源增强的校准规则是：

- 命中目标人物本人发布的内容：可以作为“本人表达”引用；
- 命中第三方发布的内容：不能把它归因给目标人物；
- 没有命中近期具体内容：保留已验证的账号主页，并标注需要手动定位；
- 服务不可用或运行环境不支持：继续使用主研究流程，不阻塞简报生成。

如果当前环境不提供这层能力，主研究流程仍然使用已经验证的账号主页或文章链接，并在简报中说明具体内容链接需要手动定位。信源增强只改善引用精度，不改变研究结果的主体结构，也不是运行这个 Skill 的硬依赖。

## 安装

### Codex

```bash
cp -R portable-pre-meeting-intel ~/.codex/skills/
```

### Claude Code

```bash
cp -R portable-pre-meeting-intel ~/.claude/skills/
```

两种环境都读取目录中的 `SKILL.md`。`agents/openai.yaml` 只提供 Codex 的界面名称，不影响 Claude Code。

如果需要检查一份已经生成的 Markdown 简报：

```bash
python3 scripts/validate_brief.py path/to/brief.md
python3 -m unittest discover -s tests -v
```

脚本检查简报中可见的结构与标注；来源是否真的被打开、人物是否对应、观点是否被正确归因，仍需对照研究时的证据记录检查。仓库中的 golden 简报是合成样例，不代表对真实人物的研究结论。

## 设计原则

1. **按时间搜索，而不是按相关性搜索**：旧的成名事件不一定是他现在正在讲的故事；
2. **差异就是信号**：本人叙述、第三方解读和社群反应要放在一起比较；
3. **人物背景写成叙事，而不是简历条目**：重点解释关键转折和底层逻辑；
4. **Talking Points 不是销售脚本**：每条问题都应具体、自然，并且和会面上下文相关；
5. **来源增强优先于来源猜测**：不能验证的链接就明确标注，不编造具体内容 URL；
6. **先看 90 天，必要时扩展到 180 天**：90 天用于捕捉当前信号；只有在证据不足以回答会面问题时才扩展，并明确记录原因。

## 信息边界

本 Skill 只整理公开信息。它不会访问私密数据，不会推断敏感个人属性，不会把社群单条评论当成事实，也会把事实、来源转述、社群观点和助手推断分开标注。
